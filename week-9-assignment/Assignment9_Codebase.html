Approach

The objective of this assignment is to explore data through a public API, such as the New York Times. The general tasks are to load, clean, and analyze the data are similar to previous assignments, this time with the new challenge of using a live source that replicates a real life work environment with automated and integrated applications. With the right permissions, we’re able to access data from another system (NYT) and connect it to ours.

Endpoint

I’ve chosen the books endpoint, which return the current ranked entries for a named NYT Best Sellers list. We are pulling from the lists hardcover-fiction and hardcover-nonfiction to answer: which books on each list have been there the longest, and how do their current ranks compare to where they stood last week?

Steps

Step 1: Create an API key and securely save it in an environment variable.

Step 2: Make the requests to an endpoint. For this assignment, I’ll use the Books endpoint. I’ll build the call with httr2 and wrap in tryCatch so we can failures are noted in the cycle.

Step 3: Parse the JSON results. I’ll use resp_body_json() to grab the results array from each response.

Step 4: Clean up the results by trimming whitespace, removing columns we won’t need or stripping any HTML tags.

Step 5: Flatten into a clean data frame.

Step 6: Analyze and build visualizations.

Data challenges

Ensuring the amount and structure of the results is the one we want back. We have limitations of number of requests per minute due to being on a Free tier, and I will need to “sleep” to give time between requests. Some potential cleaning of the data if there’s any empty or null values, that should be turned to NA in loading, if possible.

Data Fetching

Here we define the fetch_bestsellers function that’ll send a request to the Books endpoint with our API Key based on a specific list name (ex. Fiction, Non-fiction, etc.), and return the data if successful or an error if not.

fetch_bestsellers <- function(list_name) {
  resp <- tryCatch(
    request("https://api.nytimes.com/svc/books/v3/lists/current") |>
      req_url_path_append(paste0(list_name, ".json")) |>
      req_url_query(`api-key` = api_key) |>
      req_perform(),
    error = function(e) {
      stop("Request failed (list = ", list_name, "): ", conditionMessage(e))
    }
  )

  resp_check_status(resp)

  # results is a metadata wrapper — the actual books sit one level deeper
  resp_body_json(resp)[["results"]][["books"]]
}

Helper function - Stripping HTML from book descriptions

We ran into some issues with getting the plain text from the description field. We’re wrapping the response with <p>​tags in order for the input to always look like HTML to the read_html()​function, and not treat it as a file path.

strip_html <- function(x) {
  if (is.na(x) || !nchar(str_trim(x))) return(NA_character_)
  paste0("<p>", x, "</p>") |>
    read_html() |>
    html_text2() |>
    str_trim()
}

Defining fields

Here we are naming the Book fields we want to use further on for analysis after our API call, filtering out the other fields that are not needed.

parse_book <- function(book, list_name) {
  tibble(
    list_name      = list_name,
    rank           = book[["rank"]]           %||% NA_integer_,
    rank_last_week = book[["rank_last_week"]] %||% NA_integer_,
    weeks_on_list  = book[["weeks_on_list"]]  %||% NA_integer_,
    title          = str_squish(book[["title"]]       %||% NA_character_),
    author         = str_squish(book[["author"]]      %||% NA_character_),
    publisher      = str_trim(book[["publisher"]]     %||% NA_character_),
    description    = strip_html(book[["description"]] %||% NA_character_),
    isbn13         = book[["primary_isbn13"]]  %||% NA_character_
  )
}

Clean Up

df_all <- df_all |>

  # rank_last_week = 0 means the book is new this week, not ranked 0th
  mutate(rank_last_week = na_if(rank_last_week, 0L)) |>

  # weeks_on_list = 0 also flags a debut — at minimum it's been on one week
  mutate(weeks_on_list = if_else(weeks_on_list == 0L, 1L, weeks_on_list)) |>

  # catch any empty strings left after HTML stripping
  mutate(description = na_if(str_trim(description), "")) |>

  # negative = moved up, positive = moved down, NA = new this week
  mutate(
    rank_change = case_when(
      is.na(rank_last_week) ~ NA_integer_,
      TRUE                  ~ rank - rank_last_week
    )
  )

# Filter out any books that might appear twice by checking the ISBN number
